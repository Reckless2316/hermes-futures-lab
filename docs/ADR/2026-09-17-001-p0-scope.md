Claude focused remediation re-review PASS. See P0_ACCEPTANCE.md for the accepted
HEAD and two non-blocking Medium findings carried into P1.

The user requested starting with P0. MASTER_BLUEPRINT section 5 defines P0 as
specification plus CLI skeleton, although the operator's first-ticket suggestion
combines P0/P1. Deliver P0 first and retain the separate phase acceptance gate.

Build one Python 3.11+ package, with no runtime dependencies for this skeleton.
Pin Hatchling for packaging and PyYAML/JSON Schema for contract checks only.
Use YAML for the rules manifest, JSON Schema Draft 2020-12 for its shape, and JSON
for synthetic event traces and rule vectors. No database exists yet, so there is
no migration. P1 adds domain/ledger/rules/risk/session code after P0 acceptance;
later packages are created when needed instead of empty modules.

The candidate manifest records observed rules, not a promoted evaluation
rules version. Review must promote a **new** version/file with its own hash;
never relabel existing bytes as reviewed. No simulated pass/fail output in P0.

Acceptance requires Claude's disposition on the frozen diff, human acceptance of
50K Growth Evaluation scope, and resolution of ADR 003's material interpretation.
